# Phase 3B — song-reactive Unity samples and modulation bindings

**Status:** initial source implementation / Unity 6 GPU acceptance pending.
**Base:** Phase 3 recording foundation (`docs/04-recording-format.md`), with Phase 1
source clock and Phase 2 shader globals as authoritative inputs.

## Contents

- `Runtime/Motion/MotionSignalMath.cs`: seek-safe synthetic preview/reference math.
- `Runtime/Motion/MotionSignalBus.cs`: scene-wide 4-channel evaluated signal bus,
  explicitly selecting synthetic preview or a real `MotionRecordingAsset`.
- `Runtime/Motion/MotionPropertyDriver.cs`: typed light, particle and material bindings.
- `Runtime/GPU/MotionRecordingGpuBridge.cs`: optional capped float32 `GraphicsBuffer`
  of the entire native recording, with a CPU-calculated sample cursor.
- `Runtime/GPU/DanceFlowMotionSignals.hlsl`: four live signal uniforms and Shader
  Graph-compatible Custom Function `DF_GetMotionSignals` (File mode).
- `Runtime/GPU/DanceFlowMotionBuffer.hlsl`: `DF_MotionBufferSample(uint channel)`
  for target 4.5-capable shaders.
- `Samples~/SongReactiveLandscape/`: procedural terrain, trees, batched grass,
  atmospheric starfield, palette-shifted materials, a geometry-warp tower,
  URP shader, autogenerated scenes, provenance overlay and song manifest.
- `tools~/showcase-checks/export_catalogue_match.py`: optional native-only
  catalogue sampler to create finite, explicit-tempo, phase-unverified recordings.

## Song-specific sources and workflow

### Arcadians (StemLab)

The public StemLab README documents the real song in
`examples/arcadians/Arcadians - 320kbps.mp3` with 145 BPM. The ranked
mix-only analysis cites three leading *candidate* DanceRudiments patterns:
`groove_b_played` (0.739), `groove_b_grid` (0.737), and `lfo_morph` (0.724).
Those are similarities, not confidence/phase proofs. If using that pattern as
an explicitly authored preview, first install the official native
DanceRudiments package and call the build-time utility:

```sh
python tools~/showcase-checks/export_catalogue_match.py \
  --pattern groove_b_played --bpm 145 --beats 512 \
  --bpm-source "StemLab Arcadians artist-documented tempo" \
  --output ./local-assets/arcadians-groove-b.recording.json
```

This samples the *actual native* DanceRudiments pattern, rather than drawing
lookalike sinusoidal movement. It intentionally tags BPM as estimated and
phase as unverified. Confirm alignment and choose the source-pip mapping in
Unity before describing it as matching playback. Alternatively use one of
StemLab's real 2D/3D/6D/Fourier recordings derived from the full master.
StemLab's published gallery may contain downloadable `.json.gz` recordings;
decompress and import only assets with the correct source and provenance.

### The Truth is a Virus (StemLab)

StemLab reports a fitted beat-grid estimate of 109.0013 BPM, but the measured
alignment is not artist-confirmed. The Unity preset does **not** automatically
adopt this estimate for audio playback. Enable the explicit unconfirmed-tempo
option, or supply your reviewed BPM/complete source-bound beat map. Import a
corresponding measured recording and set its channel names.

### Star Lights Glow (Bass Ben & Friends)

There are at least two distinct released mixes: *Mystery Liquid Kick* and
*Anthem*. The sample manifest treats them as separate song profiles. Neither
actual audio files, exact master hashes, BPMs, corrected timelines nor matched
rudiment recordings are bundled or inferred. For each authorised local song
copy, run StemLab and review its results:

```sh
stemlab analyze "Star Lights Glow - local master.wav" \
  --output ./analysis-star-lights --profile practical
stemlab rudiments ./analysis-star-lights --top 20
stemlab generate-batch ./analysis-star-lights \
  --dimensions 2 --dimensions 3 --dimensions 6 \
  --max-candidates 24 --seed 17 \
  --output ./analysis-star-lights/motion-candidates
```

If direct recording is preferred, StemLab's documented `record-rudiment` command
can generate four named frequency bands (e.g. `band_000` to `band_003`) from the
real master. Use a reviewed BPM/beat origin and preserve file hashes and timing
provenance; do not derive a BPM from the Unity preview clock. A saved StemLab
`stemlab.beat-timeline.v1` may be applied through the existing verified
`DanceFlowClockBehaviour.UseStemLabTimeline` API using exact source bytes.

After importing the matching `dancerudiments.recording` JSON into Unity, set
`MotionSignalBus.source = ImportedRecording` in the Inspector. Choose channels
explicitly and acknowledge source equivalence or define a `RecordingTimeMapping`
against the master beat. The `SongShowcaseBootstrap` requires a separately
reviewed BPM for either Star Lights Glow mix before it will play actual audio.
The synthetic-preview mode remains available without those inputs, with a
permanent on-screen provenance label.

## Mapping design

The runtime publishes `_DanceFlow_MotionA` and `_DanceFlow_MotionB` (signed
channels and magnitudes). It also publishes `_DanceFlow_MotionAvailable` and
`_DanceFlow_MotionIsRecording`, so a shader/UI can distinguish a fallback from
a verified captured motion. The four slots are *semantic outputs*, not channel
IDs: slot 0 = wind/trunk bass, 1 = gust/percussion, 2 = palette/melody, 3 =
shimmer/atmosphere. Slot-to-source-channel mapping is configurable; no channel
is automatically assigned from its musical meaning.

BPM, beat/bar phase and loop behaviour remain owned solely by the Phase 1
`MusicalTransport`. The bus samples `DanceFlowClockBehaviour.Current` in its
`LateUpdate`, before the Phase 2 bridge's publication. A discontinuity or seek
must sample the requested pip directly, never by accumulating elapsed frames.

The GPU full-recording mirror is **opt-in**, only available on supported devices,
and bounded to 1,048,576 float32 scalars (4 MiB). All float64 source samples
remain unchanged on CPU. The buffer does not handle recording streaming, multi-
clock scopes or arrays exceeding the cap: use the four sampled channel uniforms
or a future chunked buffer adapter. The HLSL consumer must include
`DanceFlowMotionBuffer.hlsl` and use `#pragma target 4.5`; the landscape shader
uses lower-cost 4-channel uniforms on target 3.0 instead.

Default missing/misaligned channels contribute zero, while out-of-range native
recordings stop and never wrap or fabricate an endpoint. Procedural catalogue
patterns can be exported into finite recordings only through the explicit
native sampling tool, with a declared length and origin confidence.

## Geometry and GPU effects

1. **Grass**: a single mesh of 3,000 deterministic quads. UV1.x=0 at roots and
   1 at tips; musical wind and native motion blend with a small spatial gust.
2. **Trees**: 14 procedurally generated tapered trunks/branches plus grouped
   octahedral leaf clusters, with separate bark/canopy materials.
3. **Rolling terrain**: sample-stable Perlin hills, beat/gust radial ripples.
4. **Palette**: hue-axis RGB rotation using beat/bar phase and recorded channel
   2 across foliage, terrain, and the tower. Atmospheric sky/fog/light changes
   are bound separately and restore settings on disable.
5. **Warp sculpture**: a helical tower with independently controlled radial
   expansion and torsion, avoiding transformations of recorded source data.
6. **Stars**: generated batched billboard quads with shimmer-linked emission.

## Acceptance and limitations

- `python -m unittest discover -s tools~/showcase-checks -p 'test_*.py' -v`
  checks song manifest status, shader/CPU parameter names, generated geometry,
  bounded buffers and Unity `.meta` GUID uniqueness.
- `dotnet run --project tools/clock-checks/ClockChecks.csproj -c Release`
  tests additional managed preview/math parity along with the existing clock.
- Unity 6 Editor/Play Mode and GPU shader validation remain required. The sample
  can only render with URP installed and assigned; no actual rendered Unity
  screenshot or benchmark is asserted here.
- Manually test pause/seek, source ending, long sessions, shader API compatibility,
  scene rebuild/cleanup, mobile buffer fallbacks and 1000+ grass blades on a
  real GPU. Source matching requires actual authorised audio and recording data.
- No music/audio, custom model weights, artist master hashes, private analysis
  data or large mesh files are committed. The samples are kept outside the
  base package by Unity's standard `Samples~` opt-in mechanism.
