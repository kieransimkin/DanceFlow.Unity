The canonical JSON has **exactly ten** required top-level keys:
`format`, `schema_version`, `pips_per_beat`, `sample_dtype`,
`sample_decimals`, `name`, `dimensions`, `clock`, `samples`, `provenance`.
The six required clock keys are `bpm`, `bpm_status`, `bpm_source`,
`beat_zero_seconds`, `phase_status`, `start_pip`. The parser rejects additional
schema keys, duplicate keys, malformed JSON/UTF-8, duplicate/malformed channel
IDs, ragged rows, values outside [-1,1], nonfinite numbers, invalid confidence
and exceeding native limits. `provenance` is an inert object, never instructions.
It uses the existing Phase 1 `StrictJson` parser with a **recording-specific
64 MiB limit**; StemLab maps keep their **32 MiB** limit.

Every dimension is preserved, with **8,388,608 scalar values maximum** and at
least one row/channel. Native absolute pip positions are signed int32 and
**start_pip + sampleCount must not exceed int32 MaxValue**. Canonical Python
authoring normalises each sample with `round(value, 12)`; the managed importer
matches this with `Math.Round(value, 12, MidpointRounding.ToEven)`. The source
JSON SHA-256 is stored separately from the normalised binary cache SHA-256.

Captured recordings **do not loop**. Legacy XYZ compiled packs are a different
format and are intentionally rejected. Beat/BPM confidence never proves a
musical downbeat or source-audio identity.

## How to import into Unity

1. Add `com.kieransimkin.danceflow.unity` to your Unity 6 project.
2. In the Unity Editor, choose **Assets > DanceFlow > Import DanceRudiments Recording JSON...**.
3. Select a canonical `dancerudiments.recording` `.json` file, generated by
   DanceRudiments or StemLab. No Python runtime is required for import.
4. The importer validates the entire document **before writing** and creates
   two uniquely named assets under `Assets/DanceFlowRecordings/`:
   - `name.asset` — a small metadata-only `MotionRecordingAsset` ScriptableObject;
   - `name.bytes` — a separate DFR1 float64 binary sample cache (Unity `TextAsset`).
5. Select the metadata asset to inspect channel names and provenance. Click
   **Verify binary cache and exact sample extent** to recheck integrity.

Imports never overwrite another recording. On failure the importer removes
only the files it just created. Source JSON is **not** silently modified or
moved; keep your source `.json` under version control/your analysis output.
Move `.asset` and `.bytes` together via Unity's AssetDatabase to retain the
referenced GUID. For large recordings, do not add the `.bytes` to an always-loaded
scene or Resources folder.

## DFR1 binary cache format — version 1

Little-endian fields, sequentially:

| Offset | Type | Field |
| ---: | --- | --- |
| 0 | 4 ASCII bytes | `DFR1` magic |
| 4 | int32 | version (`1`) |
| 8 | int32 | dimension count |
| 12 | int32 | row count |
| 16 | int32 | signed start pip |
| 20 | float64 | recording BPM |
| 28 | float64 | beat-zero source seconds |
| 36 | 32 bytes | SHA-256 of the canonical serialised descriptor |
| 68 | float64[] | row-major, interleaved samples |

The accompanying `.asset` also records the full binary SHA-256 and original
source JSON SHA-256. The decoder verifies the hash, exact payload size,
version, BPM/origin/start, channel count and descriptor hash before allowing
sampling. Descriptor hashing includes name, channel IDs and order, row count,
source clock statuses/provenance and provenance JSON. The cache is a private
Unity interchange representation, **not** a new DanceRudiments JSON version.
No float32 conversion occurs in this CPU path.

## Managed sampling API

```csharp
using DanceFlow.Unity.Motion;

// Unity asset reference assigned through the Inspector:
MotionRecording recording = recordingAsset.OpenVerified();
int bass = recording.Descriptor.ChannelIndex("bass");

// Exact native sampling. The first/last valid absolute pip is governed
// by the capture's start_pip and sample_count, not a guessed song BPM.
double exact = recording.SampleExact(recording.Clock.StartPip, bass);

// Fractional native-pip interpolation, with no frame-time accumulator:
double smooth = recording.SampleAtPip(-31.5, bass, RecordingInterpolation.Linear);

// Source seconds use the capture's OWN constant-BPM clock:
double sourceTime = recording.Clock.SourceSecondsAtPip(-31);
double bySource = recording.SampleAtSourceSeconds(sourceTime, bass);
```

`SampleExactInto(pip, destination)` and `SampleAtPipInto(pip, destination)`
read all N channels into a caller-owned reusable array without per-sample
allocations. `TrySampleAtPip` returns false outside the recorded extent.
Integer pip reads agree with native row values; interpolation is optional and
never changes the source recording. Linear interpolation holds the last sample
inside its final pip window, but **after the exclusive end it errors/returns
false**, rather than wrapping a captured take.

## Time domain — no implicit retiming

`BeatState.SourceSeconds` always describes the original master timeline;
`BeatState.AbsoluteBeat` always uses the master song's (possibly variable BPM)
map. The recording retains an independent fixed BPM and Beat 1 origin. These
two domains are never silently merged.

- `RecordingTimeMapping.OriginalSourceSeconds()` maps the master source seconds
  into the recording's source clock. The caller must independently verify
  that the two sources represent the same source timeline; the recording JSON
  itself has **no required audio-master hash**.
- `RecordingTimeMapping.ExplicitBeatRetiming(masterBeat, recordingPip,
  pipsPerMasterBeat, acknowledgeUnverifiedPhase)` explicitly maps master beat
  coordinates to recording pips. The mapping is affine and does not imply
  an inferred downbeat. Unverified phase requires explicit acknowledgement.
- Captured recordings use `AbsoluteBeat` (source-loop phase), not the
  continuous beat coordinate, so they cannot unexpectedly wrap at an excerpt
  seam. Future advanced MotionSyncMaps may add explicit anchor warping.

Use the `MotionTransformDriver` component to map up to three named channels to
local XYZ offsets. Select a `DanceFlowClockBehaviour` and imported recording,
set channel names and metre scales, then **acknowledge source association** or
choose explicit beat retiming. An exhausted capture returns to its neutral
position, never wraps. Objects share a reference-counted recording cache
while active and release it on disable.
